# Broader public OCR benchmark protocol

Defined before implementation/inference, 2026-10-23. User authorized the recommended SROIE, TextOCR and HierText comparison. This is new comparative development evidence, not a new untouched final test. Existing model weights, inference thresholds, original manifests, dependency lock and consumed final evidence remain unchanged.

## Scope and scoring decisions

- Acquire the pinned SROIE mirror test split (361 receipts), official TextOCR validation release (3,124 images), and official HierText validation release (1,724 images). Use all available entries after the exclusions below, not model-selected examples. Record actual annotation/legibility counts rather than assuming every annotation is legible.
- Exclude the 20 prior SROIE receipt parents, every prior full-scene parent, and all 77 possible legacy TextOCR crop parents before inference. Record original source IDs and decoded pixel overlap with prior corpora. Cross-source duplicate images are reported, and source scores are never pooled. Public-pretraining overlap remains unknown.
- Compare frozen `v6-tiny` and `v6-w8-rec`, CPUExecutionProvider, one ORT/OpenCV thread, detector maximum side 960, classification disabled, existing thresholds. For word-level scoring request RapidOCR's built-in word-box output. This is an explicit benchmark output adapter; it must preserve line text/boxes on existing development fixtures before use. No ground-truth information may drive predicted word boundaries.
- Use the unmodified HierText polygon evaluator pinned to Git commit `70b6620b2b112597d8219e11eee9773a1403827c`, with its default IoU/ignore rules and case-sensitive exact text matching. HierText uses official word-level detection/E2E metrics. Apply the same evaluator to TextOCR words and SROIE text regions as a **shared protocol**, not a claim to reproduce their native leaderboard. Use native predicted lines for SROIE and native predicted words for TextOCR/HierText.
- Supplement with normalized and case-sensitive row-order CER/WER only on pages whose references contain no illegible/ignored regions. These are page-order diagnostics, not a canonical reading-order benchmark. Count excluded incomplete-reference pages separately. Do not score partially labeled screens or SRD in this suite.
- One measured full-pipeline call per image after two warmups on an existing development receipt. Latency includes decode, preprocessing, inference, line ordering and word-box postprocessing; excludes model initialization, downloading and scoring. Report per-source p50 and nearest-rank p95. Run models in sequential fresh processes; report initialization time, model artifact bytes and OS-reported peak process working set (not model-only RAM). This is one pass, not repeatable-device latency certification.
- If a process is resumed, its completion record explicitly marks memory coverage incomplete for the whole run; the reported peak then covers only the completion process. Do not claim an experiment-wide RAM comparison from partial process coverage.
- Save first predictions in checkpointed journals with pinned source/model/code/environment fingerprints. Completed runs verify without inference. Resume only an incomplete journal with matching fingerprints; reject torn lines, duplicates, missing/extra IDs and corruption. Do not change thresholds or select a model from the old final set.
- Keep downloads local and bounded: TextOCR ZIP <=8 GiB, HierText archive <=1 GiB, SROIE Parquet <=256 MiB, each annotation file <=128 MiB, each image <=16 MiB and 40 million pixels. Stream file hashing, validate archive members, and materialize selected canonical image bytes into generated paths. Preserve source/license snapshots. Benchmark-only optional dependencies use a separately pinned uv overlay; do not change `uv.lock`.

## Verification matrix

All commands run from `C:\Users\reese\tinyocr` with `uv run --locked --with-requirements benchmark-requirements.txt` (abbreviated `BENCH` below). Exact versions are recorded in that file and run evidence.

Benchmark-specific tests run with `BENCH python -m unittest discover -s tests_benchmark -v`; the existing `tests/` suite remains runnable in the original locked environment. Official polygon scoring uses the unchanged upstream core directly and does not need its Apache Beam CLI. HierText's compressed annotation download is bounded at 128 MiB and its decoded JSON at 512 MiB. ZIP member count/expanded-size bounds are 50,000 / 16 GiB; TAR bounds are 10,000 / 2 GiB. Source original caches and canonical RGB PNGs retain stored-pixel coordinates; EXIF is recorded and not applied to reference coordinates.

Pre-inference discovery amendment: preparation demonstrated that 55 SROIE test images exceed the initially proposed 25-million-pixel intake bound, with source-declared and decoded sizes matching (up to 4,961 x 7,016, approximately 34.8 MP). Raise the bound to 40 MP to support this verified source stratum while retaining a hard decode limit; RGB storage at that limit is 120 MB, well below the project memory budget. Do not discard these valid pages to satisfy the original generic intake assumption. No benchmark predictions existed when this decision was made.

Pre-inference source audit: retain the release's two exact duplicate SROIE image pairs and disclose their correlation. Retain original out-of-frame coordinates (495 HierText and 713 TextOCR regions), nine invalid TextOCR polygons and one zero-area SROIE region. The unchanged official evaluator repairs invalid geometry with Shapely `make_valid`; a zero-area reference cannot match but remains in the denominator. Do not clip, relabel, or exclude these after seeing model output. The 23 shared HierText/TextOCR scene IDs have different decoded images; report sources separately. `BENCH python -m tinyocr.audit_benchmark` records and verifies these diagnostics without OCR.
